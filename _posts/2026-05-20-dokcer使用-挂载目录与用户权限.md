## 挂载目录的基本方法

### 运行时挂载 (-v 参数)

使用 `-v` 或 `--mount` 将宿主机目录挂载到容器内：

```bash
docker run -v /host/path:/container/path image_name
```

**常用示例：**
```bash
# 挂载当前目录到容器的 /workspace
docker run -v "$(pwd):/workspace" ubuntu:22.04

# 挂载数据目录（可读写）
docker run -v /home/user/data:/app/data:rw myapp

# 只读挂载
docker run -v /home/user/config:/app/config:ro myapp
```

## Dockerfile 构建优化

### 依赖缓存优化

将 `COPY requirements.txt` 和 `RUN pip install` 放在 `COPY . .` 之前，这样只有 `requirements.txt` 变更时才会重新安装依赖，其余代码改动可复用依赖层的缓存，大幅加速构建。

**优化前（不推荐）：**
```dockerfile
COPY . .
RUN pip install -r requirements.txt
```

**优化后（推荐）：**
```dockerfile
COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt
COPY . .
```

### 使用 Python 虚拟环境

创建虚拟环境并设置为默认路径，避免与系统 Python 冲突：

```dockerfile
RUN python -m venv /opt/venv
ENV PATH="/opt/venv/bin:$PATH"
COPY requirements.txt .
RUN pip install -r requirements.txt
```

## 用户权限问题与解决方案

### 问题描述

默认情况下，Docker 容器以 `root` 用户（UID 0）运行，挂载后生成的文件也是 root 权限。这会导致：
- 宿主机编辑器无法直接编辑容器生成的文件
- 文件所有权混乱，需要频繁使用 `sudo` 操作

### 核心方案：用户映射 + 宿主机提权入口

#### 方案一：启动时对齐 UID（推荐）

启动容器时通过 `--user` 参数指定与宿主机相同的 UID 和 GID：

```bash
docker run -d \
  --name myapp \
  --user "$(id -u):$(id -g)" \
  -v "$(pwd)/data:/data" \
  your-image
```

**参数说明：**
- `$(id -u):$(id -g)`：自动填入当前用户的 UID 和 GID（通常是 `1000:1000`）
- 容器内不再以 `root` 运行，挂载目录生成的文件权限即 `$USER:$USER`

#### 需要 Root 权限时的操作

即使容器主进程以普通用户运行，仍可通过以下方式临时获取 root 权限：

```bash
# 方式1：进入容器内部交互式 shell（推荐）
docker exec -u 0 -it myapp /bin/bash

# 方式2：以 root 身份执行单条命令
docker exec -u root myapp apt-get update
```

**特点：**
- `-u 0` 或 `-u root` 直接指定 Root 用户，无需密码
- 退出后容器主进程仍保持普通用户运行

#### 解决 "I have no name!" 提示

使用 `--user` 后，容器内可能出现 `I have no name!` 的提示，虽不影响功能但不够美观。可在 Dockerfile 中提前创建对应 UID 的用户：

```dockerfile
FROM ubuntu:22.04

# 创建与宿主机普通用户相同 UID 的用户（默认 1000）
ARG USER_ID=1000
ARG GROUP_ID=1000
RUN groupadd -g ${GROUP_ID} appuser && \
    useradd -u ${USER_ID} -g appuser -m appuser

# 设置工作目录并给予写权限
WORKDIR /app
RUN chown -R appuser:appuser /app

# 切换到非 root 用户
USER appuser

# 启动命令
CMD ["/entrypoint.sh"]
```

**构建时指定 UID：**
```bash
docker build \
  --build-arg USER_ID=$(id -u) \
  --build-arg GROUP_ID=$(id -g) \
  -t myapp:latest .
```

## 完整示例

### 场景：Python 开发环境

**docker-compose.yml：**
```yaml
version: '3.8'

services:
  app:
    build:
      context: .
      args:
        USER_ID: ${UID:-1000}
        GROUP_ID: ${GID:-1000}
    user: "${UID:-1000}:${GID:-1000}"
    volumes:
      - .:/app
      - /app/__pycache__  # 匿名卷，避免缓存污染宿主机
    working_dir: /app
    command: python main.py
```

**Dockerfile：**
```dockerfile
FROM python:3.11-slim

# 安装系统依赖
RUN apt-get update && apt-get install -y \
    gcc \
    && rm -rf /var/lib/apt/lists/*

# 创建用户
ARG USER_ID=1000
ARG GROUP_ID=1000
RUN groupadd -g ${GROUP_ID} appuser && \
    useradd -u ${USER_ID} -g appuser -m appuser

# 创建虚拟环境
RUN python -m venv /opt/venv
ENV PATH="/opt/venv/bin:$PATH"

# 安装依赖（利用缓存）
COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt

# 设置工作目录
WORKDIR /app
RUN chown -R appuser:appuser /app

# 切换到普通用户
USER appuser

# 默认命令
CMD ["python", "main.py"]
```

**使用方法：**
```bash
# 启动服务
docker-compose up -d

# 进入容器调试（root 权限）
docker-compose exec -u 0 app bash

# 查看生成的文件权限（宿主机显示为当前用户）
ls -la
```

## 总结

| 场景                   | 推荐方案                                         |
| ---------------------- | ------------------------------------------------ |
| 临时运行容器           | `docker run --user $(id -u):$(id -g)`            |
| 长期开发环境           | Dockerfile 中创建用户 + docker-compose 指定 user |
| 需要 root 权限         | `docker exec -u 0` 临时进入                      |
| 避免 "I have no name!" | Dockerfile 中提前创建对应 UID 的用户             |

通过以上方案，可以实现：
- 容器生成的文件在宿主机可直接编辑
- 容器内可按需获取 root 权限
- 构建缓存优化，加速开发迭代
